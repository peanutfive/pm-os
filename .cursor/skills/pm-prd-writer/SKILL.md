# PM PRD Writer

## 核心能力

1. **需求梳理**：引导式提问，帮助 PM 从模糊想法到结构化需求
2. **PRD 撰写**：基于模板生成完整的产品需求文档
3. **用户故事编写**：将需求转化为标准用户故事格式

## 工作流程

### 流程一：需求梳理

当用户说"梳理需求"、"分析需求"或描述一个模糊的产品想法时：

1. 读取模板：`Read templates/requirement-template.md`
2. 按模板中的结构，逐步引导用户回答关键问题
3. 不要一次性抛出所有问题，每轮聚焦 1-2 个核心问题
4. 汇总后生成需求文档，保存到 `docs/requirements/YYYY-MM-DD-功能名称.md`

**引导顺序**：
- 第一轮：需求背景和痛点（"你想解决什么问题？现在用户遇到了什么困难？"）
- 第二轮：目标用户和场景（"谁会用这个功能？在什么情况下使用？"）
- 第三轮：功能范围和优先级（"这次要做哪些？哪些可以放到后面？"）
- 第四轮：验收标准（"怎样算做完了？"）

### 流程二：PRD 撰写

当用户说"写PRD"、"产品需求文档"时：

1. 读取模板：`Read templates/prd-template.md`
2. 检查是否已有对应的需求文档（`docs/requirements/` 下查找）
3. 如果有需求文档，基于它生成 PRD；如果没有，先走需求梳理流程
4. 按模板结构逐章节填写，每完成一个章节确认后再继续
5. 保存到 `docs/prds/YYYY-MM-DD-功能名称.md`

### 流程三：用户故事

当用户说"用户故事"、"user story"时：

1. 读取模板：`Read templates/user-story-template.md`
2. 将需求转化为用户故事格式
3. 为每个故事定义验收标准

## 关键提醒

- 遇到技术实现细节，标注"**[需技术评审]**"
- 遇到业务决策点，给出选项和 trade-off，标注"**[需业务决策]**"
- 遇到数据不足的地方，标注"**[需数据验证]**"
- 每份文档结尾附上"**遗留问题清单**"
